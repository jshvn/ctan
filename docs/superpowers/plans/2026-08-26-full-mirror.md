# Full CTAN Mirror Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the daily tlnet-only mirror with the hourly list-diff mirror of all of CTAN that `docs/full-mirror/taskfile-architecture.md` specifies, runnable identically inside a container, on a developer Mac, and on GitHub Actions.

**Architecture:** One `Taskfile.yml`: list dante, diff the listing against a state file kept in the bucket, fetch the delta in ≤4 GB batches, verify the signed tlnet files, upload with `aws s3 cp`, checkpoint the state after every batch. A `tools/docker/ctan/Dockerfile` (ubuntu:24.04, the same tool versions as GitHub's `ubuntu-latest`) plus two wrapper tasks (`image`, `run`) run the same Taskfile locally through Apple `container` or Docker, so macOS's openrsync and the missing local AWS CLI never matter. Three Cloudflare rulesets live as JSON in `cloudflare/`.

**Tech Stack:** go-task 3.53.1, rsync 3.2.7, AWS CLI v2 2.36.24, gnupg 2.4.4 (`gpgv`), xz 5.4.5, curl 8.5.0, `shasum` (perl), POSIX awk (mawk on Ubuntu, BWK awk on macOS), Apple `container` 1.2.2 or Docker.

**Spec:** `docs/full-mirror/taskfile-architecture.md` (called **T** below). T is the single source of truth. The other ten files in `docs/full-mirror/` are older drafts and **must be ignored** where they differ from T; do not edit any file under `docs/full-mirror/`.

## Global Constraints

- Tools inside the pipeline are exactly `rsync`, `aws` (CLI v2), `gpgv`, `shasum`, `xz`, `curl`, `task`, plus POSIX `awk`/`sed`/`sort`/`comm`/`join`/`find`. No `jq`, no `python`, no shell script files.
- Network endpoints are exactly `rsync.dante.ctan.org`, R2, `ctan.ijosh.com`, healthchecks.io, `api.cloudflare.com`.
- Task version floor 3.28.0; everything here was verified on 3.53.1.
- Every `sort`, `comm`, `join` runs with `LC_ALL=C`.
- Commit format `<type>(<scope>): <summary>`, imperative, under 75 characters, **no AI attribution of any kind** (no `Co-Authored-By`, no "generated by").
- Functions < 50 lines is N/A; `Taskfile.yml` must stay under 800 lines.
- Comments describe the current system only; never mention the old daily pipeline, "replaces", "was", or migration history.
- **Tool hygiene for executors:** Josh's `block-destructive` hook rejects any Bash command whose *text* contains `rm -rf`-style flags or `find … -delete`. The Taskfile legitimately contains `find {{.STAGING}} -mindepth 1 -delete`. Therefore: create and edit files with the **Write/Edit tools, never Bash heredocs**; make a fresh `mkdir -p` directory per test instead of clearing one; never put those idioms in a Bash step.
- `task run -- <cmd>` runs `<cmd>` inside the container with the repo mounted at `/work`. Inside the container, paths are `/work/...`. Every test below runs inside the container unless it says "host".
- Fixtures live in `fixtures/` (git-excluded via `.git/info/exclude`, already present): `ctan-list-deref.txt` (dante's raw `rsync -rL --list-only`, 538,289 lines, 2026-08-26), `upstream.txt` (496,149 lines, T's normaliser output, before the tlcontrib change in Task 3), `changed-seed.txt` (479,175 lines: the listing minus tlnet), `applied.txt`. The repo's `staging/` holds a real signed `tlpkg/` and five containers from 2026-08-25, the same day as the listing.

## Decisions fixed by this plan (T's open questions, resolved)

| # | Decision | Value |
|---|---|---|
| D1 | tlcontrib's versioned containers | dropped in the normaliser, like tlnet's (261 files, 0.46 GB) |
| D2 | `checkpoint` state after a vanished path | records **what landed** (`find staging -type f` joined to the batch), never the planned lines; this also fixes T's bug where `checkpoint` called with `B=deleted.txt` appended bare paths |
| D3 | `delete` when `MAX_BATCHES` deferred the decision batch | skipped until the hour every batch ran, so the live tlpdb never names a deleted container |
| D4 | Packer and `x`/`x.sha512`/`x.sha512.asc` | never flush a batch between a path and a longer path it prefixes (verified: same 30 batches on the seed fixture) |
| D5 | `rules` sha256 recipe | ruleset `description` = `sha256:` + sha256 of the file **with its own description line removed**, 64 hex chars; `rules` and `lint-one` use one identical `sed \| shasum` line |
| D6 | `rules` without `CF_API_TOKEN` | skipped via `status`, so the mirror runs before the two Cloudflare secrets exist |
| D7 | `RUN` directory | `{{.ROOT_DIR}}/run` (git-ignored), not `/tmp/ctan-run`, so results survive the container and are inspectable from the host |
| D8 | `retry` sleeps | `RETRY_BASE` var (default 15) scales base and jitter, so the task is testable in seconds |
| D9 | `list` | split into `list` (rsync) and `normalise` (awk + floor) so the normaliser is testable from a canned listing |
| D10 | `checkpoint` | split into `merge` (pure text, public) and `checkpoint` (merge + upload) for the same reason |
| D11 | CI | stays native on `ubuntu-latest` (same tool versions as the image); the image is for local runs and a possible future Cloudflare Containers deployment |
| D12 | Cloudflare JSON | four files written from the Rulesets API shape; they are validated by `lint` tonight and by the first live `rules` call (needs the secrets) in the morning |

### Task 3: `normalise` as its own task; drop tlcontrib's versioned containers (D1, D9)

**Files:**
- Modify: `Taskfile.yml` — task `list`

**Interfaces:**
- Produces: `task normalise RUN=<dir>` reads `<dir>/listing.txt`, writes `<dir>/upstream.txt`, fails under 400,000 lines. `list` = rsync then `normalise`.

- [ ] **Step 1: Replace `list`** (Edit tool) with:

```yaml
  list:
    desc: List dante and normalise it to RUN/upstream.txt as "path TAB size TAB mtime", byte-sorted
    set: [pipefail]
    cmds:
      - mkdir -p {{.RUN}} {{.STAGING}}
      - task: retry
        vars: {CMD: '{{.RSYNC}} -rL --list-only {{.SOURCE}} > {{.RUN}}/listing.txt'}
      - {task: normalise}

  normalise:
    desc: RUN/listing.txt (rsync --list-only) to RUN/upstream.txt; regular files only, versioned containers dropped
    set: [pipefail]
    cmds:
      # The size column may carry commas (rsync 3.x) or be blank for a zero-byte file
      # (openrsync), so it is found from the fixed-width date, not by field. tlnet's and
      # tlcontrib's versioned containers and update-tlmgr-r* are dropped here, so they are
      # never fetched, never stored, and never in the state.
      - >-
        awk -v TL="{{.TL}}" '
          /^-/ && match($0, / [0-9][0-9][0-9][0-9]\/[0-9][0-9]\/[0-9][0-9] [0-9][0-9]:[0-9][0-9]:[0-9][0-9] /) {
            path = substr($0, RSTART + RLENGTH); mtime = substr($0, RSTART + 1, RLENGTH - 2)
            size = substr($0, 11, RSTART - 11); gsub(/[ ,]/, "", size)
            if (path ~ "^systems/texlive/(tlnet|tlcontrib)/archive/.*\\.r[0-9]+\\.tar\\.xz$" || path ~ "^" TL "/update-tlmgr-r") next
            print path "\t" size + 0 "\t" mtime }' {{.RUN}}/listing.txt
        | LC_ALL=C sort > {{.RUN}}/upstream.txt
      # A truncated listing must never become a deletion list. CTAN is ~496k files.
      - test "$(wc -l < {{.RUN}}/upstream.txt)" -gt 400000
```

### Task 5: `merge`/`checkpoint` record what landed; `delete` waits for the decision batch (D2, D3, D10)

**Files:**
- Modify: `Taskfile.yml` — tasks `checkpoint`, `delete`; new task `merge`

**Interfaces:**
- Produces: `task merge B=<batch> RUN=<dir> STAGING=<dir>` writes `<dir>/applied.new` = state minus B's paths plus B's lines for files present under STAGING. `checkpoint` = `merge`, upload, rotate, empty staging.

- [ ] **Step 1: Replace `checkpoint`** (Edit tool) with:

```yaml
  merge:
    desc: RUN/applied.new = the state minus B's paths, plus B's lines for the files that are in STAGING
    set: [pipefail]
    requires: {vars: [B]}
    cmds:
      # Only what landed enters the state: a path that vanished upstream between listing
      # and fetch is dropped, so the state never names a key the bucket lacks. Called with
      # deleted.txt (bare paths, empty staging) this is a pure drop. 0.1 s on 496k lines.
      - (cd {{.STAGING}} && find . -type f | sed 's|^\./||' | LC_ALL=C sort) > {{.RUN}}/landed.txt
      - >-
        awk -F'\t' 'NR == FNR { drop[$1] = 1; next } !($1 in drop)' {{.B}} {{.RUN}}/applied.txt
        | cat - <(LC_ALL=C join -t "$(printf '\t')" {{.RUN}}/landed.txt {{.B}}) | LC_ALL=C sort > {{.RUN}}/applied.new

  checkpoint:
    internal: true
    requires: {vars: [B]}
    set: [pipefail]
    cmds:
      - {task: merge, vars: {B: '{{.B}}'}}
      - xz -T0 -c {{.RUN}}/applied.new > {{.RUN}}/applied.new.xz
      # One PutObject; the old file or the new one is in the bucket, never half.
      - aws s3 cp {{.AWS_FLAGS}} {{.RUN}}/applied.new.xz {{.S3}}/{{.STATE}}
      - mv {{.RUN}}/applied.new {{.RUN}}/applied.txt
      - find {{.STAGING}} -mindepth 1 -delete
```

# ctan

[![sync](https://github.com/jshvn/ctan/actions/workflows/sync.yml/badge.svg)](https://github.com/jshvn/ctan/actions/workflows/sync.yml)

## How to use

TeX Live and TinyTeX both use `tlmgr`:

```sh
tlmgr option repository https://ctan.ijosh.com/systems/texlive/tlnet/
tlmgr update --self --all
```

For a fresh install, give the installer the same URL:

install-tl -repository https://ctan.ijosh.com/systems/texlive/tlnet/

Any other CTAN path works the same way, for example
`https://ctan.ijosh.com/macros/latex/contrib/hyperref.zip`. Directory URLs redirect to the
matching page on ctan.org, because R2 serves files, not listings.

## How it works

Every hour GitHub Actions lists CTAN's master (dante), diffs the listing against the listing
the previous run left in the bucket, fetches only the changed files in batches, verifies the
signed TeX Live files (`texlive.tlpdb`, the installers and the `tlmgr` updaters, with the TeX
Live key fingerprint pinned) and every package container against the tlpdb's checksums, and
uploads. Every step is in the
[`Taskfile.yml`](https://github.com/jshvn/ctan/blob/main/Taskfile.yml).

**Is it fresh?**

```sh
curl -s https://ctan.ijosh.com/timestamp
```

## Why use this?

`tlmgr`'s default repository is CTAN's mirror rotation: every request lands on a different
volunteer mirror, and any one of them can be unreachable, on a slow connection, behind on
TLS, or a few days stale. This is one origin behind
[Cloudflare's network](https://cloudflare.com/network), never more than about an hour
behind the master.

## Want your own?

1. Fork [this repo](https://github.com/jshvn/ctan).
2. Create an R2 bucket named `tlnet`, an API token with Object Read & Write scoped to it,
   and a custom domain pointing at the bucket. Set `HOST` to that domain in `Taskfile.yml`
   and in `cloudflare/*.json`, and put your own links and text in `site/index.html`.
3. Add the repository secrets `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`;
   optionally `HEALTHCHECK_URL` (a healthchecks.io ping URL) and `CF_API_TOKEN` plus
   `CF_ZONE_ID` (a token with the zone's Cache Rules, Transform Rules and Single Redirect
   edit permissions) so the landing page and directory redirects are applied from
   `cloudflare/`.
4. Actions -> sync -> Run workflow with `seed` checked and `max_batches` at 40. The first
   run uploads everything (about 133 GB, a few hours); every run after that pushes the
   hourly delta. Storage past R2's free 10 GB costs about $1.86 a month.

To run the pipeline locally, `task run -- task --dry sync` renders it inside the toolbox
image (Apple `container` or Docker); with `AWS_*` variables exported, `task run -- task sync`
runs it for real.

Pull requests are welcome.

An hourly mirror of all of `CTAN/` (dante's `rsync://rsync.dante.ctan.org/CTAN/`) on
Cloudflare R2, served at `https://ctan.ijosh.com/` with every CTAN path at the bucket root.
About 496,000 objects and 133 GB; the largest file is 6.87 GB. Storage is the only bill,
about $1.86 a month; the pipeline refuses to run past 175 GB upstream.

The design and its evidence are in `docs/full-mirror/taskfile-architecture.md`; the other
files in that directory are earlier drafts and are not authoritative.

Everything is in a few files:

- `Taskfile.yml`: the whole pipeline. `task sync` runs
  `clock -> rules -> list -> state -> rebuild? -> diff -> plan -> tlpdb -> batches -> delete -> reconcile? -> smoke -> report -> ping -> page`,
  where `batches` runs `fetch -> verify -> publish -> purge? -> checkpoint` per batch.
- `aws.config`: single-part uploads under 4 GiB, 512 MiB multipart parts above.
- `cloudflare/*.json`: the zone's rulesets (bypass cache, `/` -> `/.site/index.html`,
  directory URLs -> ctan.org). `rules` applies one only when its stamped sha256 differs.
- `tools/docker/ctan/Dockerfile`: the toolbox image with the runner's tool versions.

- `site/index.html`: the landing page, uploaded to `.site/index.html`.

`README.md` is for users. Operational detail belongs here and in Taskfile comments.

## Constraints

- No shell scripts. Logic lives in `Taskfile.yml`; workflows install tools and run one task.
- Tools are exactly `rsync`, `aws` (CLI v2), `gpg` (for `gpgv`), `shasum`, `xz`, `curl`,
  `task`. Network endpoints are exactly dante, R2, the public domain, healthchecks.io and
  `api.cloudflare.com`.
- Objects sit at the bucket root under CTAN's own paths. `.state/` and `.site/` are the two
  reserved prefixes; CTAN has no dot-prefixed root entry, so they cannot collide.
- Secrets are exactly six: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`,

  `rules` is skipped.

## Must knows

Each of these is a bug that has happened or a bill that would. Do not undo them.

- **The mirror is a list-diff, never a local tree.** The runner has 14 GB; the tree is 133 GB.
  `list` takes dante's `rsync -rL --list-only`, `diff` compares it with the state file the
  last run left in the bucket, and only the delta is fetched, in batches of at most 4 GB.
  The bucket is listed only in the daily `reconcile`.
- **The state line is `path TAB size TAB mtime`, path first, `LC_ALL=C` sorted.** Whole-line
  `comm` mis-pairs lines in any other order. Every `sort`, `comm` and `join` runs with
  `LC_ALL=C`, and every bucket listing is re-sorted because R2 lists keys out of byte order.
- **The state records what landed.** `merge` joins the batch against `find staging -type f`,
  so a path that vanished upstream between listing and fetch never enters the state.
- **No versioned containers.** `tlmgr` requests `archive/foo.tar.xz`; upstream stores
  `foo.r123.tar.xz` and symlinks to it. `normalise` drops tlnet's and tlcontrib's
  `*.r[0-9]*.tar.xz` and `update-tlmgr-r*`, and `fetch` uses `-L`, so each is stored once.
- **A missing state file fails the run** unless `SEED=true` (empty bucket) or
  `RECONCILE=true` (rebuild it from a bucket listing joined to upstream on size). Treating a
  missing state as empty would re-upload 133 GB.
- **The decision batch is last.** tlnet's `tlpkg/` and the root files (`timestamp` last of
  all) go in the final batch, after every container, and `verify` refuses that batch unless
  every container the tlpdb names is in the bucket after this run. `delete` waits for the
  hour in which every batch has landed, so the live tlpdb never names a removed container.
- **Never `aws s3 sync`.** `publish` is `aws s3 cp --recursive` (one PutObject per file,
  never a destination listing). Deletions come from `diff`, 1,000 keys per `DeleteObjects`,
  with the `Errors` array checked because the CLI exits 0 on it.
- **`checkpoint` is the last step of a batch.** The state is written once per batch, after
  the upload succeeded, as one PutObject. A run that dies anywhere repeats at most one batch
  the next hour. A run that stops at `MAX_BATCHES` with batches left is a success.
- **Cron lateness is normal.** Scheduled runs start 15 to 45 minutes after :41 and a slot
  can be dropped. `clock` records the lateness, `report` prints it, and `reconcile` keys on
  the slot's hour (03 UTC), not the clock's.
- **`index.html` at the root is CTAN's.** The landing page is `.site/index.html`, served at
  `/` by the transform rule in `cloudflare/transform-rules.json`.
- **Do not trust the job log for counts.** `report` counts from `RUN` (`run/`), never the log.
- **A failed run is the only alert.** healthchecks.io emails when its grace passes without
  `ping`, which also catches GitHub disabling the schedule after 60 commit-free days.
- The edge cache is off (`CACHE=off`: one bypass rule, no purges). `CACHE=on` swaps in
  `cache-rules.json` and purges changed keys per batch; switch it on only when R2 Class B
  reads exceed 5M a month for two months.
